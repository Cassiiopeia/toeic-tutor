# toeic-tutor — 토익 RC · 토익스피킹 튜터 설계

2026-09-08. 토익 RC(Reading) 와 토익스피킹을 **문제 풀이 → 근거 말하기 → 직접 교정 → 다시 → 카드 → 복습** 루프로
훈련하는 공개 레포. paper-study → interview-prep 으로 이어진 튜터 루프를 그대로 가져오되, 채점 근거를 "논문 원문"·"사실 원장"
대신 **유형·함정 카탈로그**에 두고, 사용자의 자산을 "이야기 뱅크" 대신 **오답 노트(RC) · 내 템플릿과 소재(토스)** 에 둔다.

**누구나 fork 해서 자기 수준에 맞게 쓴다.** 그래서 사람에 따라 달라지는 것은 전부 `my/` 에 있고 git 에 올라가지 않는다.

---

## 0. 결정된 전제

| # | 결정 | 이유 |
|---|---|---|
| 1 | 레포 하나, 트랙 둘 (`rc/` · `speaking/`) | 같은 시기에 같이 공부한다. 프로필·카드·기록을 한 곳에서 |
| 2 | 리스닝은 다루지 않는다 | 조수가 소리를 못 낸다. 리딩만 |
| 3 | 토스 답변은 **타이핑** | 조수가 소리를 못 듣는다. 발음·억양은 채점 불가로 명시. 내용·구조·문법·어휘·분량은 본다 |
| 4 | 공개 레포 · 개인 데이터는 `my/` 에 모아 gitignore | 남에게 필요한 건 규칙·카탈로그·규격서·스크립트다. 내 점수·오답은 남에게 쓸모없다 |
| 5 | 문제 은행 없음. **유형별 예시 2~3개 + 생성 규격서** | 은행은 외워지고 함정이 고정된다. 규격서가 촘촘하면 조수가 매번 새로 만든다 |
| 6 | 실제 기출·교재 문제를 옮기지 않는다 | 공개 레포. 형식만 따른다 |
| 7 | 성적은 사용자가 붙여넣는다 | 성적 조회 페이지(exam.toeic.co.kr/result/scoreList.php)는 로그인이 필요해 조수가 못 읽는다 |
| 8 | `main` 단일 브랜치 · projectops 없음 · 커밋은 템플릿이 바뀔 때만 | 개인 파일은 커밋 대상이 아니다 |

## 1. 사용자 부담은 0

사용자는 채팅에서 답만 한다. 프로필·기록·카드·오답 노트·템플릿 버전·커밋은 전부 조수가 한다. 스크립트는 조수가 `python3` 로 돌린다.

## 3. 절대 규칙 (interview-prep 에서 이식, 이 레포용으로 바꾼 것)

1. **답만 맞으면 통과가 아니다.** RC 는 정답 + 유형 판단 + 근거 한 줄. 토스는 뼈대 + 내 소재.
2. **한 번에 문제 하나.** 세트는 모의(mock)·진단(init) 모드에서만.
3. **틀리면 직접 고쳐준다.** 어느 신호를 놓쳤고 어느 함정(T-번호)에 걸렸는지. "다시 풀어 보세요" 만 하지 않는다.
4. **본인 말로.** 오답 이유·패러프레이징·어휘 뜻·토스 템플릿은 사용자가 쓴다. 조수가 대신 채우지 않는다. 시중 템플릿은 v0 (남이 쓴 것).
5. **매 턴 문제를 다시 적는다.** 다시 풀라고 할 때 문제 원문(지문·선지)이 그 턴에 다시 있어야 한다. 스크롤을 올리게 하는 순간 훈련이 끊긴다. (interview-prep 2026-09-04 「버린 것」)
6. **문제를 낼 때 해설을 같이 주지 않는다.** 정답·해설은 판정 뒤에만.
7. **튜터 구조 피드백은 즉시 규칙으로.** 사용자가 답 내용이 아니라 진행 방식을 지적하면 그 자리에서 CLAUDE.md(공통 결함) 또는 `my/tutor-log.md`(이 사용자 취향)를 고치고, 끊긴 자리로 돌아간다.

## 4. `/toeic init` — 진단

새로 fork 한 사람이 처음 여는 모드. `my/` 가 없으면 조수가 `python3 scripts/init.py` 로 뼈대를 만들고 시작한다.

1. **묻는다** (한 번에 하나씩): 최근 LC/RC 점수 (성적 조회 페이지 안내 — 로그인 필요, 사용자가 붙여넣음. 없으면 "모름") · 목표 RC 점수 · RC 시험일 · 토스 경험 유무 · 토스 목표 등급 · 토스 시험일 · 스스로 느끼는 약점 (파트 · 시간 부족 · 어휘 · 문법).
2. **RC 진단 세트 22문제**를 모의 모드로 한 번에 낸다. Part 5 10문제 (품사 2 · 동사 2 · 준동사 1 · 전치사/접속사 2 · 대명사/관계사 1 · 어휘 2) · Part 6 1지문 4문제 · Part 7 단일 1지문 (3문제) + 이중 1세트 (5문제). 세트 전체 제한 시간 20분을 안내한다. 사용자는 답과 걸린 시간을 적는다. 유형별 정오가 프로필의 첫 약점이 된다.
3. **토스 진단 2문항.** Q7 (30초 답 = 60~75단어) 하나 · Q11 하나를 타이핑. 뼈대 유무 · 분량 · 문법으로 출발 등급 추정 (발음 제외).
4. **소재 캐기.** 사용자의 일상 소재 (직장 · 통근 · 취미 · 건강 · 돈 · 가족 · 동네) 대여섯 개를 한 줄씩 받아 `my/speaking/materials.md` 초안으로.
5. `my/profile.md` 에 레벨 · 약점 · `prescriptions.md` 에서 뽑은 처방 (우선 파트 · 세션당 문제 수 · 시간 목표) · `my/progress.md` 에 다음 세션 시작점.

점수가 없어도 진단 세트 결과만으로 시작한다. 점수는 `debrief` 로 나중에 넣는다.

## 5. RC 훈련 (`/toeic rc`)

```
1. 조수: my/progress.md → review.py due → log.py stats (약점) → my/sessions/ 최신 → my/profile.md
2. 한 줄로 알린다 — "지난번 Part 7 연계 문제에서 두 번 걸렸고, 복습 3장 먼저"
3. 복습 카드 먼저. 카드는 같은 문제가 아니라 같은 유형·같은 함정의 **새 문제**로 묻는다
4. 문제 하나. 유형은 밝히지 않는다 — 유형 판별이 실력이다
5. 사용자: 정답 + 유형 판단 + 근거 한 줄. Part 7 은 정답 + 근거 문장 위치 + 오답 하나가 왜 오답인지
6. 판정 ○△✗ → 걸린 곳 → 근거 (카탈로그 유형 · T-번호) → 문제 다시 적고 "다시"
7. ✗ 는 다시 풀기 최대 2회 (4지선다라 3회는 의미 없다). 넘으면 정답·해설 전부 + 카드
8. 2~3문제마다 앞 오답 유형을 새 문제로 되묻는다
9. ✗·△ 는 오답 노트에. 오답 이유는 사용자가 자기 말로 쓴다. 조수는 그 문장이 카탈로그와 맞는지만 본다
10. 매 문제 log.py add
```

### 채점 잣대 셋

| 잣대 | 묻는 것 |
|---|---|
| **정답** | 맞았나 |
| **근거** | 왜 그게 답인지 — 카탈로그의 신호(빈칸 앞뒤 구조 · 시간 단서 · 근거 문장)와 맞나 |
| **함정** | 어느 오답이 어떤 함정(T-번호)인지 짚었나 |

| 판정 | 뜻 | 조수가 하는 말 |
|---|---|---|
| ○ | 정답 + 근거가 신호와 맞음 | 짧게 확인. 심은 함정을 한 줄로 밝힌다. 다음 문제 |
| △ | 정답인데 근거를 못 댐(찍음) · 근거가 틀림 · Part 7 근거 문장을 잘못 짚음 | "답은 맞는데 근거가 X 라고 하셨습니다. 이 문제의 신호는 Y 입니다 (P5-품사 · T-03)." → 근거만 다시 |
| ✗ | 오답 | "C 를 고르셨는데 그건 T-07 (지문 단어 그대로 재사용) 입니다. 근거 문장은 두 번째 문단." → 다시 |

### 힌트 사다리 (막혔을 때)

| 단계 | 조수가 주는 것 |
|---|---|
| 1 | 유형 힌트 ("품사 자리 문제입니다") |
| 2 | 구조 신호 또는 근거 문단 지목 ("빈칸 앞이 관사, 뒤가 명사" · "세 번째 지문의 날짜를 보세요") |
| 3 | 오답 하나를 제거하며 이유 |
| 4 | 정답 + 해설 전부 + 카드 |

### 문제 고르기와 난이도

- 약점 유형 60% · 무작위 40%. 약점은 `log.py stats` 가 낸다 (아래 §9).
- 난이도 3단계: 기본 → 실전 → 고난도. 최근 10문제 정확도 80% 이상이면 한 단계 올린다. 60% 미만이면 내린다.
- 시간 감각: 훈련 모드는 시간을 재지 않는다. 시간은 mock 에서 잰다.

## 6. 토스 훈련 (`/toeic speaking`)

```
1. 조수: my/progress.md → review.py due → my/speaking/templates.md (어느 문항 뼈대가 아직 v0 인가) → materials.md
2. 복습 카드 (표현 · 뼈대 · 소재) 먼저
3. 문항 하나. 처방(§8)에서 우선 문항. Q5-7 은 준비 없이 바로 타이핑, Q8-10 은 표 읽고 바로, Q11 은 45초 메모 후 타이핑
4. 사용자: 답
5. 판정 → 걸린 곳 → 다시 쓰기. 최대 3회
6. ○ 난 답은 my/speaking/templates.md 에 내 템플릿 새 버전으로. 두 번 ○ 면 '확정'
7. 매 문항 log.py add (결과 o/t/x · 메모에 척도 점수)
```

### 채점 잣대

| 잣대 | 묻는 것 | ✗ |
|---|---|---|
| **내용** | 질문에 답했나 · 표 정보가 정확한가(Q8-10) · 입장이 명확한가(Q11) | 질문과 다른 답 · 표 정보 오류 · 입장 없음 |
| **구조 · 분량** | 뼈대(첫 문장 → 이유 → 예시 → 마무리) · 단어 수 | 60초 답이 80단어 · 이유 없이 나열 |
| **문법 · 어휘** | 시제 · 관사 · 수일치 · 같은 단어 반복 | 문장이 안 끝남 · 같은 동사 5회 |
| _발음 · 억양_ | **채점 불가.** 등급 추정에 "발음 제외" 를 단다 | — |

분량 기준 (타이핑 단어 수 = 말했을 때 시간): 15초 30~35 · 30초 60~75 · 60초 130~150.

ETS 척도로 점수를 매기고 ○△✗ 로 환산한다. Q3-10 은 0~3 (3 ○ · 2 △ · 1 이하 ✗), Q11 은 0~5 (4~5 ○ · 3 △ · 2 이하 ✗).

### 문항별 재료 (조수가 만든다 — `speaking/generation.md`)

| 문항 | 재료 | 규격 |
|---|---|---|
| Q1-2 | 강세·끊어읽기·연음 표시한 지문 | 자습. 조수가 채점하지 않는다. 광고·안내방송·뉴스 톤 40~60단어 |
| Q3-4 | **장면 카드** — 장소 · 인물 수 · 동작 · 배경 · 소품 6~8개 요소를 글로 | 사진 대신. 뼈대: 장소 → 중심 인물 → 주변 → 배경 → 느낌 |
| Q5-7 | 설문 상황 (전화 설문 · 친구 대화) + 질문 셋 | Q5·Q6 15초 짧은 질문 (when/how often/what), Q7 30초 이유 요구 |
| Q8-10 | 표 하나 — 일정표 · 이력서 · 행사 프로그램 · 청구서 중 하나 | Q8 기본 정보 · Q9 **틀린 정보 정정** · Q10 여러 항목 나열 (30초) |
| Q11 | 의견 주제 — 찬반 · 둘 중 선택 · 장단점 | 45초 메모 후 130~150단어 |

### 내 템플릿 · 내 소재

- `speaking/templates/*.md` 의 v0 는 공개 자료를 종합한 **남의 뼈대**다. 사용자가 자기 문장으로 v1 을 쓴다. 두 번 ○ 면 확정. 버전은 지우지 않는다.
- Q11 · Q7 의 이유는 늘 `my/speaking/materials.md` 의 소재 5~6개에서 꺼낸다. "뭐 할 말이 없다" 는 소재가 없어서다. init 에서 캐고, 세션마다 하나씩 문장으로 굳힌다.

## 7. 문제 생성 규격서 — `rc/generation.md` · `speaking/generation.md`

이게 없으면 에이전트는 쉬운 문제만 낸다. 규격서가 조수를 묶는다.

### RC 공통

- 문제 번호는 실제 시험대로 (Part 5 101~130 · Part 6 131~146 · Part 7 147~200). Directions 원문을 세트 앞에 붙인다.
- 지문은 인용문 또는 코드 블록으로 원문 그대로. 선지는 (A) (B) (C) (D).
- 정답 분포를 고르게. 세트에서 같은 글자가 3연속이면 다시 만든다.
- **문제마다 심은 함정 T-번호를 조수가 정해 두고, 판정 뒤 해설에서 밝힌다.** 함정 없는 문제는 내지 않는다 (기본 난이도만 예외).
- 비즈니스 맥락 9종을 돌린다 — 사무 · 인사 · 마케팅 · 물류 · 재무 · 행사 · 부동산 · 여행 · 고객 서비스.
- 실제 기출 · 교재 문제 · 그 변형을 쓰지 않는다. 형식만.
- 문제와 함께 해설을 주지 않는다.

### Part 5 (30문항 · 12~25단어)

| 유형 | 선지 구성 규칙 | 필수 함정 |
|---|---|---|
| 품사 자리 | 같은 어근 4형태 (명·동·형·부) | 형태만 비슷한 오답, 명사가 둘 (사람/사물) |
| 동사 (수일치·시제·태) | 같은 동사 4형태 | 주어와 동사 사이에 긴 수식어, 시간 단서가 문장 끝에 |
| 준동사 | to부정사 · 동명사 · 분사 · 원형 | 앞 동사의 목적어 형태 (enjoy -ing vs decide to) |
| 전치사 vs 접속사 | 전치사 2 + 접속사 2 | 뜻은 같고 자리가 다른 짝 (despite/although · during/while) |
| 대명사 · 관계사 | 격 4형태 또는 관계사 4개 | 선행사가 사람인지 사물인지 · 재귀대명사 |
| 어휘 | 같은 품사 4개, 그중 2개는 뜻이 비슷 | 뜻은 맞는데 연어(collocation)가 틀림 |
| 비교 · 도치 · 병치 | 구문 4형태 | — |

### Part 6 (4지문 × 4문항 · 지문 80~130단어)

- 지문 종류: 이메일 · 공지 · 기사 · 광고 · 회람 · 편지. 4지문에 겹치지 않게.
- 빈칸 4 = 문법 1 + 어휘 1 + 연결어/시제 1 + **문장 삽입 1**.
- 문장 삽입 선지 4개는 전부 지문 주제와 관련되게 만든다. 주제만 보고 못 고르게. 정답은 앞뒤 문장의 대명사 · 연결어 · 시제로만 갈린다.
- 시제 문제는 빈칸 문장만 봐서는 못 풀게 — 앞 문장의 시점이 단서.

### Part 7 (54문항)

| 구성 | 지문 | 문항 | 단어 수 |
|---|---|---|---|
| 단일 10지문 | 147~175 | 지문당 2~4 | 100~300 |
| 이중 2세트 | 176~185 | 세트당 5 | 합 300~450 |
| 삼중 3세트 | 186~200 | 세트당 5 | 합 400~600 |

- 지문 종류 9가지: 이메일 · 문자 메시지 체인 · 공지 · 광고 · 기사 · 양식(신청서·설문) · 일정표 · 청구서/영수증 · 온라인 채팅. 세트 안에서 종류를 섞는다 (이메일 + 일정표 + 답장).
- 문제 유형 조합: 이중·삼중은 **연계 문제 최소 1개** (두 지문을 합쳐야만 풀림) · NOT/EXCEPT 최대 1개 · 동의어 1개 · 추론 1개. 문자 체인 · 채팅에는 **의도 문제** ("At 10:15, what does Ms. Park mean when she writes …") 를 넣는다.
- 함정 규칙: 오답 선지에 지문 단어를 **그대로** 재사용하고 정답은 패러프레이즈 · 비슷한 날짜·이름·금액을 둘 이상 등장시킨다 · 연계 문제의 근거는 반드시 서로 다른 지문에 나눠 둔다 · NOT 문제의 세 오답은 지문에 흩어져 있게.
- 세트 하나가 훈련 모드의 "문제 하나" 다 (지문 + 문항 2~5개). 답은 문항별로 받는다.

### 토스

- Q3-4 장면 카드: 장소 1 · 중심 인물 1~2 (동작 · 옷) · 주변 인물 · 배경 2~3 · 소품 2~3. 실내/실외 · 사람 수를 돌린다.
- Q5-7: 주제 20종 (여가 · 쇼핑 · 교통 · 기술 · 음식 · 여행 · 운동 · 독서 · 날씨 · …) 을 돌린다. Q7 은 "which / why / would you rather" 형.
- Q8-10: 표는 코드 블록으로 실제 양식처럼 (제목 · 날짜 · 시간 · 항목 · 담당자 · 비용). Q9 의 "틀린 정보" 는 조수가 질문 안에 심는다.
- Q11: 주제 30종 (직장 · 교육 · 기술 · 생활 · 사회). 찬반 / 둘 중 선택 / 장단점 / 셋 중 가장 중요한 것.

## 9. 스크립트

### `scripts/log.py` — 풀이 기록

저장 `my/log.md` 마크다운 표. 열: `날짜 | 트랙 | 문항 | 유형 | 함정 | 결과 | 메모`.

- 트랙 `rc` / `spk`. 문항 `P5` `P6` `P7S` `P7D` `P7T` / `Q3` ~ `Q11`.
- 유형은 카탈로그 코드 (`품사` `동사` `연계` `NOT` …), 함정은 `T-07` 또는 `-`. 결과 `o|t|x`. 메모는 토스 척도 점수 등.

```
python3 scripts/log.py add rc P5 품사 T-03 x "형용사 자리에 부사"
python3 scripts/log.py add spk Q11 - - t "3/5 이유 하나"
python3 scripts/log.py stats [rc|spk] [--days N]
```

`stats` 는 문항별 · 유형별 · 함정별 정답률과 문제 수를 내고, **n ≥ 4 이고 정답률 < 70% 면 「약점」** 으로 표시한다. `--days` 로 최근 구간만. 최근 7일과 그 이전을 나란히 보여 추세를 낸다.

### `scripts/review.py` — 복습 카드

interview-prep 것을 이식. 저장 `my/cards.md`. 영역 값은 `P5` `P6` `P7` `T-07` `Q11` `Q8-10` `vocab` `phrase`. 로직 동일 (간격 1 → 3 → 7 → 21 → 60일, `o` 올림 · `t` 제자리 · `x` 1일).

카드에 답을 적지 않는다. 카드는 "같은 유형·같은 함정의 새 문제" 로 묻는다. 오답 노트 id (`W-012`) 를 근거에 적어 조수가 변형 문제를 만든다.

### `scripts/init.py` — my/ 뼈대

`my/` 가 없으면 `my.example/` 를 복사해 만든다. 있으면 건드리지 않고 알린다. 질문은 하지 않는다 (조수가 채팅으로).

### 테스트

`tests/test_review.py` (이식) · `tests/test_log.py` (add · stats 정답률 · 약점 판정 · 기간 필터) · `tests/test_init.py` (생성 · 덮어쓰지 않음). 임시 디렉터리를 저장소로 쓴다. `python3 -m pytest -q`.
